Git 是什么

Git 是一个分布式版本控制系统，用于记录项目文件随时间的变化并支持不同开发线的并行演化。其核心价值在于：

  • 提供对任意历史版本的可重现访问；
  • 维护分支间的独立性与合并能力；
  • 支持本地离线操作与远程协作。

Git 强调“快照式”存储，即每次提交均记录项目状态的引用，而非单纯存储差异。

Git 与 GitHub 的区分

Git 是版本控制工具，负责本地仓库的状态管理；GitHub 是基于 Git 的远程托管平台，提供协作、代码评审与备份服务。

常见托管平台还包括 GitLab、Gitee、Bitbucket 等。对于单机项目，Git 即可满足版本管理需求；对于团队协作，则需要远程仓库作为共享与同步机制。

Git 的基本模型

Git 的状态由三部分构成：

  • 工作区（working tree）：当前编辑的文件；
  • 暂存区（index）：准备提交的内容快照；
  • 本地仓库（HEAD）：已提交的历史记录。

日常命令概览

  • git status：显示当前状态；
  • git diff：显示工作区与暂存区或历史版本之间的差异；
  • git add <file>：将指定文件变更加入暂存区；
  • git add .：将所有变更加入暂存区；
  • git commit -m "..."：创建提交；
  • git log：查看提交历史；
  • git log --oneline --graph --decorate：简洁图形化历史视图。

冲突处理

冲突表示 Git 无法自动合并不同变更。基本处理步骤：

  1. 编辑冲突文件；
  2. 解决 <<<<<<< / ======= / >>>>>>> 区分的内容；
  3. 保存并 git add；
  4. 完成合并或继续 rebase。

学习建议

推荐学习顺序：

  1. 熟悉 git status、git add、git commit、git log；
  2. 理解分支与合并；
  3. 掌握远程仓库同步；
  4. 学习撤销与恢复操作；
  5. 扩展到交互式提交和代码评审流程。

常见误区

  • 将 git pull 视为完全安全；
  • 误用 git commit --amend 修改已推送提交；
  • 认为 .gitignore 会删除已跟踪文件；
  • 将分支等同于标签。
